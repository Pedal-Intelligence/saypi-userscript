### Addendum — live finding on this PR's own required check (discovered after the static work above)

This audit's own PR (#670) triggered its required `e2e` check as usual on push, and it
**failed** — not the local-sandbox browser-cache gap described above (a different,
CI-only failure). The "Install Playwright Chromium + OS deps" step
(`npx playwright install --with-deps chromium`) failed in ~1s:

```
BEWARE: your OS is not officially supported by Playwright; installing dependencies for ubuntu26.04-x64 as a fallback.
Cannot install dependencies for ubuntu26.04-x64 with Playwright 1.60.0!
Failed to install browsers
Error: ERROR: Playwright does not support chromium on ubuntu26.04-x64
```

GitHub's `ubuntu-latest` runner label now resolves to Ubuntu 26.04; the repo's pinned
`@playwright/test@^1.60.0` cannot install Chromium's OS deps there. This is
diff-independent (PR #670 only adds a doc file) and reproduces on every PR going
forward — a genuine regression in the required merge gate, not something the static
checklist above could catch (it ran `npm ci`/`e2e:build`/`npm test` locally in this
sandbox, which has its own unrelated browser-cache mismatch, and corroborated harness
health via *past* green CI runs — the last of which, on `main`@`e7498a3`
(2026-10-12), predates whatever GitHub-side rollout caused this). `test (22.x)` and
`e2e-firefox` are both unaffected (neither installs a Playwright browser on Chromium;
`e2e-firefox` drives Firefox via geckodriver/Marionette) — confirmed green on this
same PR run.

**Filed as #671** (`awaiting-founder` — the fix touches `.github/workflows/e2e.yaml`,
a founder-gated path, so no agent can push it without `founder-approved`). This is
this cycle's one genuine new drift item: the constitution's claim that the required
gate is `test (22.x)` + `e2e`, both green, is no longer true in practice until #671 is
resolved.
